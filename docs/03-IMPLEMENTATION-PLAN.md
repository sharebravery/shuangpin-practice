# 双拼练习实现计划

版本：v1.1  
项目名称：双拼练习（Shuangpin Practice）  
执行方式：六阶段线性实现  
核心要求：前一阶段验收通过后再进入下一阶段，不并行扩张需求。

## 1. 全局执行规则

所有阶段必须遵守：

1. 第一版只有一个主页面。
2. 不开发登录、数据库和后端。
3. 不建立独立设置页。
4. 共享状态优先使用 Zustand。
5. 组件内部临时状态使用 `useState`。
6. 双拼编码和出题逻辑使用纯函数。
7. shadcn/ui 已有组件时必须优先使用。
8. 不使用原生交互元素重造组件。
9. 不复制许可证存在争议的旧项目业务源码。
10. 题库和方案规则重新整理并编写测试。
11. 不提前开发后续版本功能。
12. 每阶段结束后项目必须能够正常运行。
13. 每阶段结束后执行类型检查、测试和构建。
14. 新想法先记录，不中断当前阶段。

## 第一阶段：初始化项目与设计系统

### 目标

建立可运行、可部署、具备组件约束的项目骨架。

### 任务

- 创建 Next.js App Router 项目。
- 开启 TypeScript 严格模式。
- 配置静态导出。
- 配置 Tailwind CSS。
- 初始化 shadcn/ui。
- 显式选择 Base UI。
- 配置主题 Token。
- 安装 Zustand。
- 安装 next-themes。
- 安装 Lucide Icons。
- 配置 Vitest。
- 配置 Playwright。
- 配置 ESLint。
- 建立目录结构。
- 编写 README。
- 建立第三方来源说明。

### 安装 shadcn/ui 组件

只添加第一版需要的组件：

```text
button
select
switch
popover
drawer
dialog
alert-dialog
tooltip
accordion
progress
separator
input
badge
sonner
```

### 组件约束

配置 ESLint 或代码审查规则：

- 业务代码禁止原生 button。
- 业务代码禁止原生 select。
- 业务代码禁止原生 dialog。
- 禁止 `div + onClick` 模拟控件。
- `components/ui` 排除该限制。

### 验收

- 首页可打开。
- 浅色、深色和系统主题可切换。
- Button、Select、Popover 和 Drawer 可正常渲染。
- Zustand Store 可读取和更新状态。
- Vitest 可运行。
- Playwright 可打开首页。
- 静态构建成功。
- 组件约束生效。

## 第二阶段：实现双拼规则和题库

### 目标

在正式练习界面之前，完成经过测试的核心数据和算法。

### 任务

- 定义双拼方案类型。
- 定义单字和词组题目类型。
- 实现拼音标准化。
- 实现声母和韵母拆分。
- 实现零声母处理。
- 实现双拼编码。
- 实现答案校验。
- 整理小鹤双拼映射。
- 整理微软双拼映射。
- 整理自然码双拼映射。
- 整理搜狗双拼映射。
- 整理 200 个常用单字。
- 整理 50 个常用词组。
- 编写题库验证函数。
- 实现随机出题。
- 实现连续去重。
- 实现简单错题权重。

### 数据要求

每道题必须：

- 有稳定 ID。
- 有明确拼音。
- 可以被四种方案编码。
- 不包含歧义读音。
- 不依赖第三方运行时 API。

### 测试要求

每种方案至少测试：

- 普通声母。
- 复合韵母。
- 零声母。
- 特殊韵母。
- 无效输入。
- 至少十组人工确认样例。

题库测试：

- 没有重复 ID。
- 没有空拼音。
- 所有题目均可编码。
- 词组文字数与拼音数一致。

### 验收

- 四种方案共享同一编码接口。
- 全部题库数据通过验证。
- 双拼算法完全独立于 UI 和 Zustand。
- 单元测试通过。
- 项目仍可正常构建。

### Vitest

确认覆盖：

- 四种方案编码。
- 零声母和特殊韵母。
- 答案判断。
- 出题去重。
- 错题权重。
- Store Actions。
- 正确率。
- 持久化字段。
- 数据恢复。
- 题库完整性。

### Playwright

实现四条流程：

1. 首页完成一道单字题。
2. 切换双拼方案并完成一道题。
3. 修改设置、刷新并确认设置保留。
4. 移动端打开 Drawer 并完成一道题。

### 组件专项审查

搜索业务代码中的：

```text
<button
<select
<dialog
onClick
```

逐项确认：

- 是否使用了 shadcn/ui。
- `onClick` 是否绑定在正确交互组件上。
- 是否存在 div 模拟按钮。
- 是否重复实现弹窗、开关或下拉框。
- 是否有不必要的组件依赖。

### 状态专项审查

确认：

- 共享业务状态均由 Zustand 管理。
- 没有第二套 React Context 业务状态。
- 没有组件直接读写 localStorage。
- 主题只由 next-themes 管理。
- 领域纯函数不依赖 Store。
- 弹窗开关没有不必要地进入 Store。
